3. UAT Data Document – contains approved UAT account numbers, banks, BICs, IDs, currencies.

5. Flow Diagram – illustrates request flow, validation layer, orchestration, downstream systems.

You MUST analyze ALL attachments before generating test cases.

----------------------------------------------------
CRITICAL DATA RULES
----------------------------------------------------

- DO NOT use production-like data.
- DO NOT copy sample IDs directly.
- Use ONLY values from UAT data attachment.
- If required UAT data is missing, use placeholder:
  "UAT_TBD_<FIELD_NAME>"

- Keep all payloads internally consistent and realistic.

----------------------------------------------------
SYSTEM UNDERSTANDING REQUIREMENT
----------------------------------------------------

Use:

• Requirement document → to extract business rules & acceptance criteria
• README → to understand validation rules, mandatory fields, enum constraints
• Flow diagram → to understand processing stages and downstream behavior
• Sample JSON → for message structure only
• UAT data → for safe test values

Generate test cases aligned with actual system behavior and validation logic.

----------------------------------------------------
TEST CASE COVERAGE REQUIRED
----------------------------------------------------

Generate 25–40 test cases minimum (based on complexity).

Include:

1. Happy Path
   - Valid payment initiation
   - All mandatory fields correct
   - Valid country/currency/account match

2. Business Rule Validation
   - Country-specific logic
   - Conditional mandatory fields
   - Billing/transaction code logic
   - Status notification behavior

3. Negative Cases
   - Invalid account numbers
   - Unsupported currency
   - Invalid method/type
   - Duplicate message_id or end_to_end_id
   - Invalid enum values

4. Missing Data Cases
   - Missing debtor
   - Missing creditor
   - Missing transaction object
   - Missing mandatory nested fields

5. Invalid Format Cases
   - Invalid date-time format
   - Invalid UUID format
   - Invalid numeric precision
   - Wrong data types (string instead of number)

6. Edge / Boundary Cases
   - Zero amount
   - Negative amount
   - Extremely large amount
   - Max length strings
   - Special characters

7. Flow-Based Scenarios (from Flow Diagram)
   - Validation layer rejection
   - Orchestrator rejection
   - Downstream failure simulation
   - Status push notification behavior

8. Security / Robustness
   - Injection characters
   - Long string overflow
   - Unexpected object fields
