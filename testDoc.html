Executive summary

Separate ingestion (build a knowledge base) from generation (retrieve + produce tests). Store raw artifacts in S3, store operational state (jobs, audit, checkpoints) in MongoDB, and store retrieval indexes (chunks, embeddings, full-text) in Postgres + pgvector. Run ingestion and large generations on async workers behind a queue to handle retries and rate limits safely.

No brand references: This page contains no Friday.ai content and is suitable for generic architecture review.

RAG ingestion pipeline

Pseudocode showing connectors, parsing, chunking, embeddings, deduplication, and checkpointing.

Stages

1) Discover changes (webhooks preferred; scheduled sync as fallback) 2) Fetch raw content + metadata (paged; rate-limit aware) 3) Store immutable raw snapshots in S3 (versioned keys) 4) Parse & normalize (HTML/MD/code → text + metadata) 5) Chunk (token-aware, overlapped, stable boundaries) 6) Embed (retry + circuit breaker; model/version tracked) 7) Upsert into Postgres+pgvector (chunks, embeddings, FTS fields) 8) Update checkpoints + audit in MongoDB

Pseudocode

def ingest_source(source): ckpt = mongo.checkpoints.get(source.id) changes = discover_changes(source, since=ckpt.cursor) for item in changes: raw = fetch_with_backoff(source.api, item, etag=item.etag) s3_uri = s3.put_object( key=f"{tenant}/{source.kind}/{item.external_id}/{item.revision}.json", body=raw.bytes ) doc = parse_to_text(raw, content_type=item.type) chunks = chunk(doc.text, max_tokens=700, overlap=120) for ordinal, ch in enumerate(chunks): chunk_id = stable_hash(tenant, source.kind, item.external_id, item.revision, ordinal) vec = embed(ch.text, model="gemini-embedding-001", dims=768) pg.upsert_chunk( chunk_id=chunk_id, text=ch.text, metadata={...,"s3_uri": s3_uri, "revision": item.revision}, tsv=to_tsvector(ch.text), embedding=vec ) mongo.checkpoints.update(source.id, cursor=changes.new_cursor, status="ok")

Retrieval and generation

Hybrid retrieval + two-pass generation + deterministic validation gates.

Hybrid retrieval

1) Scope filters (tenant/project/system/module + freshness) 2) Lexical candidates (Postgres FTS / tsvector + GIN) 3) Vector candidates (pgvector ANN) with same filters 4) Merge+dedupe (RRF / weighted score) 5) Build context pack with citations (chunk ids + source pointers)

Generation

Pass A: Test Plan (schema JSON) - scenarios + coverage tags - evidence required per scenario - open questions if evidence missing Pass B: Test Cases (schema JSON/XML) - stable IDs + deterministic naming - evidence required per test step Pass C: Validation - JSON schema / XSD - domain rules, dedupe, forbidden placeholders - fail closed: do not publish invalid outputs
